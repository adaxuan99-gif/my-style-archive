# 维护与路线图

## 第一阶段维护

- 每月导出备份并实际检查 ZIP 有照片；每季度在独立测试项目做一次恢复演练。
- 每月看 Supabase Usage 的数据库、Storage 和流量。达到约 70% 时先备份并规划容量，不自动升级。
- 休眠恢复只在自己的 Supabase 控制台操作；查看通知，避免错过恢复期限。
- 如果照片越来越多，优先保证备份完整；归档不释放空间，因为照片仍在。永久删除才释放，而且不可撤销。
- 使用强密码、保护管理账号；新设备登录后检查数据，公用设备用后退出。
- 项目使用依赖锁文件。每季度在开发分支检查依赖更新、运行类型检查、数据库测试、浏览器测试和构建，再部署。
- 数据库有新版本时添加新的编号迁移文件，不修改已经运行过的初始迁移来升级线上环境。任何删除性迁移先确认并备份。
- 监控主要依靠你自己的服务控制台；不接第三方分析、不把照片或资料发给日志服务。

## 第二阶段：让衣服组合起来

1. 先实现穿搭及 outfit_items 联合用户外键，支持叠穿；保存图片拼贴，不合成真人图。
2. 删除衣服前显示被哪些穿搭使用，并优先归档；历史日记保存快照，不能因为今天改了一套搭配就篡改过去。
3. 穿搭日记同日多条，记录舒适度与满意度；实际次数由日记衣服快照计算，不用主观状态冒充穿着次数。
4. 购物候选放在“我的”入口，规则相似度按分类、颜色、版型、标签解释得分，用户手动确认重复。
5. 每新增表同步补 RLS、双用户测试与备份格式。

## 第三阶段：与现有 ChatGPT 协作

- 单品、多件、穿搭、购物候选与全档案分别生成结构化资料。
- 优先 iPhone 原生分享；不可用则复制文字、下载 JSON/文本和照片。不得声称已经与 ChatGPT 自动同步。
- 每个分析模板区分审美吸引力、实际适合度、购买必要性；证据不足明确说明，不要求 AI 迎合。
- AI 回复由你复制回来，保存日期、对象、内容、是否认同和补充意见。
- 灵感照片独立存储，不混入实际拥有的库存。
- 风格历史只追加，旧总结可回顾；偏好条目可以编辑、删除。

## 仍需明确的限制

- 当前无自动云备份任务；依赖手动导出及你自己的保存习惯。
- 未实现全身照片合成、自动识别、抠图或 AI 图像查重。
- 无离线修改和冲突自动合并；网络异常保留编辑弹层并提示重试，已保存记录通过版本保护。
- iOS HEIC 能力与拍照授权由系统决定，必要时转换 JPEG。
- 当前“偏好”是多个可编辑长文本，不是第三阶段逐条偏好与历史版本系统。
- 免费服务不能保证永久免费或始终可用，数据可迁移和备份是长期维护的基础。
