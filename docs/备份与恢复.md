# 备份与恢复

## 推荐习惯

第一次录入成功后就试一次导出与恢复验收。之后每月一次，大量录入后额外备份。至少留两份：自己的电脑一份，自己管理的另一处安全位置一份。备份包含私密照片和购买信息，不要发到公共网盘。

Supabase Free 不是永久保管承诺，不能把云端唯一副本当作备份。导出操作只有下载到你自己的“文件”或电脑上才算完成，界面显示成功不代表你已经妥善保管。

## 手机完整 ZIP

“我的” → 下载完整 ZIP 备份。应用先取得同一数据库快照，再下载每张照片，全部完成后打包。不漏掉归档衣服。不把缺图包称作成功备份。

文件结构：

```
archive.json        完整资料、编号、计数器、照片映射、校验值、版本号
photos/<uuid>.jpg   实际照片
 garments.csv       便于表格查看的清单
说明.txt             简短恢复提示
```

CSV 不是恢复文件；JSON + 全部照片才是完整备份。每张照片有 SHA-256 校验值，可发现传输或手动修改造成的损坏。校验值不是数字签名，不证明备份来源可信。

导出时尽量不要同时在另一设备编辑照片；如果期间删除照片导致下载失败，稍后重新导出，不会给出不完整成功提示。

## 恢复规则

“我的” → 选择备份恢复 → 等待检查 → 查看衣服和照片数量 → 确认恢复。

- 格式版本不支持、文件缺失、照片大小或校验不一致：开始上传前拒绝。
- 同 UUID、编号、资料、照片清单均相同：跳过，重复导入不会生成重复衣服。
- 同 UUID 内容不同，或同编号指向另一件衣服：整个资料事务回滚，现有资料不变。
- 新资料：保留旧编号、UUID、创建日期，照片路径换成当前登录用户的目录。
- 已存在风格档案：保留，不用旧备份覆盖最近修改。需要旧内容时可查看 ZIP 的 profile 字段，人工复制到风格档案。
- 自定义分类合并去重，最大编号计数器只提升不降低。
- 当前版本不支持自动合并同一件衣服的两个不同修改版本，也不擅自重编号。冲突时建议在一个新的空 Supabase 项目恢复，或先人工对照处理，不能直接清空原衣柜。
- 新项目迁移时，可创建新账号恢复：用户 UUID 会重新绑定。若在同一数据库中恢复到另一个账号，原 UUID 若已被占用会拒绝，以防跨账号访问。

## 中断与部分失败

照片逐张上传，已经存在且内容完全相同的照片会跳过；最后的资料提交是一个数据库事务。网络中断后用同一包重试，不会把一半资料变成成功恢复。

如果照片已上传但最终资料提交失败，会留下未关联照片。24 小时后可在“我的” → 清理未关联照片，或先继续恢复。已关联照片有数据库权限保护，不能被该清理动作删除。不要同时在多个设备上恢复同一个包。

发生冲突时保留 ZIP、截图错误信息、重新读取衣柜。不要用“永久删除”作为默认修复方式。

## 手机容量上限与电脑大容量备份

为了控制 Safari 内存使用，本版手机 ZIP 限制照片总量 180MB，压缩包体积另有少量资料余量。实际可处理大小仍受设备可用内存影响；操作时保持页面前台，失败时使用下面电脑工具。

超过 180MB 不会悄悄导出部分照片，也不用无法恢复的 CSV 冒充完整备份。项目附带 `scripts/archive.ts`：按照片逐个写入磁盘，每次只处理一张照片，没有 180MB 总量限制（依然受磁盘空间、数据库和网络限制）。它使用普通账号登录，不需要 service_role。

1. 在项目目录复制 `.env.example` 为 `.env.local`，填好项目公开配置。
2. 新建 `.env.backup`（本地私密配置，已被 `.gitignore` 排除）：

```ini
ARCHIVE_EMAIL=你自己的登录邮箱
ARCHIVE_PASSWORD=你自己的密码
```

3. 在电脑终端运行，目标使用一个新空目录：

```sh
pnpm exec tsx --env-file=.env.local --env-file=.env.backup scripts/archive.ts export ./my-backup-2026-10-08
```

4. 看到“完整备份成功”后，复制整个目录到安全位置。可以用系统压缩功能生成 ZIP；超过手机大小上限时仍应使用电脑恢复。
5. 在已确认的目标项目配置下运行：

```sh
pnpm exec tsx --env-file=.env.local --env-file=.env.backup scripts/archive.ts restore ./my-backup-2026-10-08
```

6. 使用后删除 `.env.backup`，不要把密码配置、私人照片和备份上传到源代码仓库。更不要发到聊天中。

电脑导出最后才写入 `archive.json`，中断的目录不应视为完整备份。重新导出可覆盖该目录中的同名文件。建议每次选择新目录，避免混淆两个时间点。

## 跨平台迁移

JSON 的 schema 版本目前是 1。UUID、代码、资料、照片尺寸与文件映射都有保存，不依赖 Supabase 的临时图片地址。迁移时可继续使用 PostgreSQL 与任意私有对象存储，但需要重建权限规则，不能简单把全部照片改成公开 URL。

未来每增加一种数据类型（穿搭、日记、购物、灵感、AI 反馈），必须同步升级导出和恢复格式，保留旧版本迁移器后再发布。
